01
הרעיון

מה יוצרים — ולמה הכתובת נשארת קבועה

זהו פרויקט משולב: לוח מזג אוויר חי לנתניה נפתח בטלפון לאחר סריקת קוד QR שמודפס בהבלטה שחורה על מחזיק מפתחות לבן. דף האינטרנט מתעדכן בנפרד מהמחזיק: אם שומרים על כתובת האתר, אין צורך להדפיס QR חדש בכל שינוי תחזית או עיצוב.

GitHub Pages→QR→OrcaSlicer→Flashforge AD5X

המודל הדו־צבעי הודפס בהצלחה ב־AD5X עם IFS פעיל. במדריך הזה נפריד בין קובץ תלת־ממד, פרויקט Orca ו־G-code שמפעיל את המדפסת.

02
אתר

בונים אתר מזג אוויר חי — בלי שרת

  1. צרו index.html עם HTML, CSS ו־JavaScript. הפרויקט הזה כולל גם sports.js ו־sports.css לתחזיות גלישה — שמרו את שלושתם באותה תיקייה.
  2. קבעו מיקום מזג אוויר: 32.3215, 34.8532 ואזור זמן Asia/Jerusalem. לתחזית ימית משתמשים בנקודת ייחוס בים: 32.33, 34.80.
  3. הביאו JSON מ־Open-Meteo Forecast API ומ־Marine API. הציגו טמפרטורה, רוח, משבים, משקעים, גלים, סוואל, כיוון ומחזור גלים ותחזית לפי שעה.
  4. השתמשו בעברית כברירת מחדל ובאנגלית כחלופה; החליפו בין dir="rtl" ל־dir="ltr". שמרו בחירת שפה ב־localStorage.
  5. רעננו את הנתונים כל 15 דקות והציגו מועד תוקף ומקור לכל תחזית. אם מידע חסר, הציגו ״לא זמין״ במקום להמציא ערך.

הנתונים מהמודלים הם תחזיות ולא מדידות חוף. לשם השוואה יש קישורים למכשירי תחנת חדרה (טמפרטורת מים) ולגלים וזרמים.

03
פרסום

מעלים את האתר ל־GitHub Pages

  1. נכנסים ל־GitHub ויוצרים מאגר Public, לדוגמה netanya-weather.
  2. במאגר ריק לוחצים על uploading an existing file שב־Quick setup. במאגר קיים: Add file → Upload files.
  3. מעלים index.html, sports.js, sports.css ושומרים בעזרת Commit changes.
  4. פותחים Settings → Pages → Deploy from a branch → main → /(root) → Save. אם האתר כבר נפרס באמצעות Actions, שומרים על התצורה הקיימת.
  5. פותחים את כתובת ה־HTTPS בטלפון ובודקים עברית, אנגלית ונתונים. הכתובת הפעילה בפרויקט הנוכחי:

https://haymvi.github.io/netanya-weather/

ה־QR חייב להכיל את כתובת האתר המפורסם, לא את כתובת קובץ המקור ב־GitHub.

04
QR

מייצרים QR וקטורי שניתן להדפסה

  1. העתיקו את כתובת האתר הפעילה למייצר QR שמאפשר ייצוא SVG.
  2. בחרו מודולים שחורים על רקע לבן, ללא סמל במרכז. שמרו מסביב אזור שקט של ארבעה מודולים לפחות, רצוי בתוך שטח הבסיס הלבן.
  3. ייצאו SVG עם המודולים השחורים; סרקו את התמונה בטלפון ובדקו שהיא פותחת את האתר.
  4. העבירו את הנתונים לגאומטריית CAD: כל מודול שחור חייב להפוך למשטח מוצק מוגבה, לא רק לצבע או תמונה המודבקת על הדגם.

גודל כל מודול צריך להתאים לרזולוציית הנחיר. לפני סידור סופי בדקו את הקוד גם לאחר החיתוך לשכבות.

05
תלת־ממד

בונים בסיס, מודולים בולטים וטבעת

יוצרים שני אזורים גאומטריים באותו מיקום XY: בסיס לבן עם טבעת ו־מודולי QR שחורים מעל הבסיס. אפשר ליצור שני גופי STL/3MF נפרדים, או לייבא מודל STL אחד ולשייך חומרים לפי אזור גובה ב־OrcaSlicer.

חלק בדגם הבדיקהגובה Z מתוכנןחומר
בסיס + טבעת0–0.40 mmלבן / פילמנט 1
מודולים בולטים0.40–0.80 mmשחור / פילמנט 2
גובה כולל נומינלי0.80 mmשני צבעים

דגם הבדיקה הקיים היה ברוחב של כ־41.43 מ״מ ובגובה כולל טבעת של כ־47.88 מ״מ. שמרו על טבעת מחוברת לבסיס, חור פתוח ומשטחים תקינים. בצעו הדפסת בדיקה לפני תלייה על צרור מפתחות: טבעת בעובי 0.4 מ״מ דקה ושבירה יחסית.

אלה מידות הגאומטריה הנומינליות. גובה השכבות בקובץ G-code בפועל נקבע לפי פרופיל החיתוך — יש לבדוק אותו ב־Preview, ולא להסיק אותו רק מהשם “4 שכבות”.

06
OrcaSlicer

משייכים שני פילמנטים בפרויקט Orca

  1. פותחים OrcaSlicer / Orca-Flashforge ובוחרים מדפסת Flashforge AD5X עם נחיר 0.4 מ״מ.
  2. לעבודה חוזרת פותחים את קובץ הפרויקט QR_4_CAMADAS.3mf שכבר מכיל את שיוך שני החומרים. לפרויקט חדש מייבאים את גוף הבסיס והמודולים כשני חלקים מיושרים, או מבצעים Color Painting לפי Height Range אם הגאומטריה מאוחדת.
  3. מגדירים Filament 1 = PLA לבן ו־Filament 2 = PLA שחור; מוודאים שהבסיס והטבעת משויכים ל־1 והמודולים העליונים ל־2.
  4. מגדירים פרופיל שכבות מתאים. אם המטרה היא 2+2 שכבות בגודל 0.20 מ״מ, מגדירים גם את השכבה הראשונה וגם את השכבות הרגילות ל־0.20 מ״מ. פרופיל עם 0.16 מ״מ לשכבות רגילות יפיק חלוקה אחרת.
  5. בוחרים Slice plate → Preview → Filament. בודקים שהגאומטריה התחתונה לבנה, המודולים העליונים שחורים וקיימת החלפת כלי בין האזורים.

שני צבעים במסך אינם מספיקים בפני עצמם: בדקו שהחלקים משויכים לפילמנטים 1 ו־2, ושבשורות ה־G-code נוצרת החלפה אמיתית.

07
G-code

מייצאים G-code עם פקודות T0 ו־T1

  1. לאחר חיתוך מוצלח, בוחרים Export plate sliced file ושומרים את קובץ .gcode של ה־AD5X. זהו הקובץ שמשמש בפועל להדפסה.
  2. לצורך עריכה עתידית שומרים בנפרד גם File → Save Project As כ־.3mf. קובץ 3MF של הפרויקט אינו תחליף לקובץ ההדפסה החתוך.
  3. אפשר לפתוח את ה־G-code בעורך טקסט ולוודא פקודת T0 לחומר הראשון ו־T1 בעת המעבר לאזור השחור. בדקו את מיקום המעבר ואת גובה Z ב־Preview.
  4. שמרו את הפרופיל, הגרסה והקבצים של ההדפסה המוצלחת כדי לשכפל את ההליך בלי לצבוע את המודל מחדש.
T0   ; white PLA, filament 1
...
T1   ; black PLA, filament 2

זהו קטע להמחשה של פקודות בחירת כלי, לא קובץ G-code שלם. פקודות T0/T1 מעידות על התכנון בקובץ; להפעלה הפיזית של החלפת הצבע חייבים להפעיל IFS במדפסת.

08
הדפסה

מדפיסים ב־AD5X — מפעילים Enable IFS

זהו שלב חובה: לאחר שבוחרים את קובץ ההדפסה במדפסת, חייבים להפעיל Enable IFS ✓ לפני Start/Print.

  1. טוענים את שני חוטי ה־PLA ל־IFS: ערוץ פיזי 1 = לבן; ערוץ פיזי 2 = שחור. מוודאים שהמדפסת מזהה את שניהם.
  2. מעבירים ל־AD5X את .gcode שנחתך עבור פרופיל המכונה הנכון, בעזרת USB או תהליך ההעברה הנתמך.
  3. במסך המדפסת בוחרים את קובץ ה־G-code. בשלב שאחרי בחירת הקובץ מאתרים ומסמנים Enable IFS.
  4. לפני תחילת העבודה בודקים שהאפשרות מופעלת. רק לאחר מכן מתחילים בהדפסה.
  5. צופים בהחלפה: לאחר שכבות הבסיס הלבן המדפסת אמורה לעבור אוטומטית לפילמנט השחור ולייצר את המודולים המוגבהים.

לפי מסמכי Flashforge, במצב G-code המיפוי לערוצי IFS נעשה לפי מספרי הפילמנטים שבקובץ — T0 לפילמנט הראשון, T1 לשני. לעומת זאת, ל־3MF חתוך קיימת זרימת הגדרת ערוצים נפרדת. ממשק ההפעלה עשוי להשתנות בין גרסאות תוכנה.

09
בדיקה

בודקים את התוצאה ושומרים קובץ ייצור

  1. ממתינים לקירור המשטח ומסירים בעדינות את המחזיק.
  2. בודקים שהבסיס והטבעת לבנים, שהמודולים השחורים בולטים ושהגבולות בין הצבעים חדים.
  3. סורקים את ה־QR שמודפס בפועל בטלפון, ולא רק את התמונה או Preview. בודקים שהסריקה פותחת בדיוק את כתובת האתר.
  4. בודקים שהטבעת אינה נשברת בשימוש המתוכנן. לשימוש יום־יומי רצוי להכין גרסה עבה יותר לאחר בדיקה.
  5. שומרים ביחד את STL (גאומטריה), 3MF (פרויקט עם צבעים ופרופיל) ו־G-code (הוראות ההדפסה), כולל גרסת Orca והגדרות המכונה.

בפרויקט הזה החלפת הצבע בהדפסה הפיזית אושרה. בדיקת סריקה של כל מחזיק מודפס נשארת פעולה נפרדת שיש לבצע לפני חלוקתו.

10
עדכונים

מעדכנים את האתר בלי להדפיס QR חדש

  1. משנים את תוכן index.html, sports.js או sports.css באותו מאגר.
  2. שומרים ב־GitHub באמצעות Commit וממתינים לפרסום GitHub Pages.
  3. מעדכנים בדפדפן ובודקים את אותו קישור. אם משנים קבצי CSS/JS, ניתן להשתמש בפרמטר גרסה כדי למנוע שימוש בעותק ישן מהמטמון.
  4. שומרים תמיד על הנתיב https://haymvi.github.io/netanya-weather/. הקוד הפיזי ממשיך להפנות אליו.

תחזית מזג האוויר משתנה עם הנתונים מה־API; אין צורך לייצר G-code חדש כדי לעדכן תחזיות, טקסטים או גרפים באתר.

01
The idea

What we are building — and why the URL stays fixed

This project connects a live Netanya weather dashboard to a physical keyring carrying raised black QR modules on a white base. Scan the QR with a phone to open the website. The page can be updated at any time, without printing another QR, as long as its public URL remains unchanged.

GitHub Pages→QR→OrcaSlicer→Flashforge AD5X

The two-colour model has been successfully printed on an AD5X with IFS enabled. This guide distinguishes the 3D geometry, the editable Orca project and the machine-ready G-code.

02
Website

Build the live weather site without a server

  1. Create index.html using HTML, CSS and JavaScript. This project additionally loads sports.js and sports.css for surf data; publish all three together.
  2. Set the weather location to 32.3215, 34.8532 with timezone Asia/Jerusalem. Use an offshore marine reference of 32.33, 34.80.
  3. Fetch JSON from the Open-Meteo Forecast API and Marine API. Show temperature, wind, gusts, rainfall, waves, swell, wave direction/period and hourly outlooks.
  4. Default to Hebrew, with English available. Switch between dir="rtl" and dir="ltr" and save the language choice in localStorage.
  5. Refresh data every 15 minutes. Display forecast-valid timestamps and sources. Show “unavailable” for missing information instead of inventing readings.

Model data are forecasts, not beach measurements. Provide independent links to Hadera water-temperature observations and wave/current observations.

03
Publishing

Publish the site on GitHub Pages

  1. Sign in at GitHub and create a Public repository, e.g. netanya-weather.
  2. For an empty repository click uploading an existing file under Quick setup. For a populated repository select Add file → Upload files.
  3. Upload index.html, sports.js, sports.css and click Commit changes.
  4. Go to Settings → Pages → Deploy from a branch → main → /(root) → Save. Preserve an existing Actions deployment if your repository uses one.
  5. Open the HTTPS site on a phone and test Hebrew, English and weather data. This project's address is:

https://haymvi.github.io/netanya-weather/

Encode the published website URL, not the GitHub source-file address, into the QR code.

04
QR code

Generate a printable vector QR code

  1. Copy the published website address into a QR generator that exports SVG.
  2. Choose black modules on white, without a logo obscuring the matrix. Preserve a quiet zone of at least four modules on every side, ideally within the white base.
  3. Export the black module paths as SVG; scan the image with a phone and check that it opens the website.
  4. Convert the vector shapes to CAD geometry: every black module must become solid raised geometry, not merely an image or texture applied to the model.

Choose a module size that the nozzle can reproduce; verify the QR again after slicing.

05
3D model

Model the base, raised QR and keyring loop

Prepare two geometric regions in the same XY position: a white base with an integral keyring loop, and the black QR modules raised above it. You may export two aligned meshes or use one STL and assign its upper height region to filament 2 in OrcaSlicer.

Test model partNominal Z rangeMaterial
Base + loop0–0.40 mmWhite / filament 1
Raised QR modules0.40–0.80 mmBlack / filament 2
Nominal total0.80 mmTwo colours

The test geometry was approximately 41.43 mm wide and 47.88 mm tall including the loop. Keep the loop connected to the base and the hole open. For use as a daily keyring, remember that a 0.4 mm thick loop is mechanically delicate; validate strength before producing many copies.

These are the model's nominal dimensions. Actual printed layers are determined by the slicing profile: check the real G-code preview rather than inferring them from a “four layers” filename.

06
OrcaSlicer

Assign two real filaments in OrcaSlicer

  1. Open OrcaSlicer / Orca-Flashforge and select the Flashforge AD5X, 0.4 mm nozzle machine profile.
  2. For this exact job, open the working project QR_4_CAMADAS.3mf, which already has the two material assignments. For a new project, import aligned white and black components or use Color Painting → Height Range on a single suitable mesh.
  3. Set Filament 1 = white PLA and Filament 2 = black PLA. Verify that the base and loop use filament 1 while the raised QR modules use filament 2.
  4. Set the actual layer profile. If you want exactly 2+2 layers at 0.20 mm, set both first-layer and regular-layer height to 0.20 mm. A 0.16 mm regular-layer preset produces a different layer count.
  5. Choose Slice plate → Preview → Filament. Inspect the bottom white region, top black geometry and the planned change between them.

Do not rely on colour appearance alone. Confirm that materials 1 and 2 are assigned and that the sliced machine instructions contain a real tool change.

07
G-code

Export machine G-code containing T0 and T1

  1. After a successful slice, select Export plate sliced file and save the AD5X .gcode. This is the file the printer will execute.
  2. Separately save an editable File → Save Project As .3mf. The project file and the sliced machine file serve different purposes.
  3. You can inspect the G-code as text and confirm T0 selects the first filament and T1 selects the second at the black raised region. Also check the transition's actual Z position in Preview.
  4. Retain the successful printer profile, project and sliced file together for repeatable production.
T0   ; white PLA, filament 1
...
T1   ; black PLA, filament 2

These are illustrative tool-selection lines, not complete machine G-code. T0/T1 confirm a planned change; the printer still needs IFS enabled to perform it.

08
Print

Print on the AD5X — switch ON Enable IFS

Mandatory step: after selecting the print file on the printer, turn ON Enable IFS ✓ before Start/Print.

  1. Load both PLA filaments into the IFS: physical channel 1 = white; channel 2 = black. Confirm both are recognised by the machine.
  2. Transfer the correctly sliced AD5X .gcode via USB or another supported upload path.
  3. Select the G-code file on the AD5X screen. On the screen that follows file selection, locate Enable IFS and activate it.
  4. Verify that IFS remains enabled before starting the job, then initiate printing.
  5. Watch the transition: after the white base layers, the AD5X should automatically switch to black and print the raised QR modules.

According to Flashforge's G-code workflow, the printer maps filaments to IFS channels according to their numbers in the sliced file: T0 = first material, T1 = second material. Sliced 3MF files use a separate channel-configuration flow. Screen wording may vary by firmware version.

09
Validation

Verify the result and save your production files

  1. Let the build plate cool, then remove the keyring carefully.
  2. Confirm that the base and loop are white, the QR modules are raised black, and colour boundaries are clean.
  3. Scan the actual printed object with a phone — not just the source image or slicer Preview. Make sure it opens exactly the published site address.
  4. Assess the loop's strength for the intended use. A thicker version is preferable for a durable everyday keyring.
  5. Keep the STL (geometry), 3MF (materials and slicer setup) and G-code (print commands) together, including the Orca and printer profiles.

For this project, the two-colour change has been physically confirmed. Scanning every printed piece is a separate quality-control step before distribution.
