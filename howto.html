הרעיון: קיצור דרך פיזי למזג האוויר

מחזיק מפתחות לבן נושא קוד QR שחור ומובלט. סריקה בטלפון פותחת את עמוד מזג האוויר בנתניה. הכתובת קבועה, ואת האתר אפשר לעדכן בלי להדפיס מחזיק חדש. חשוב לשמור על שם המאגר ועל הכתובת שפורסמה: שינוי שלהם עלול לשבור קודים שכבר הודפסו.

The idea: a physical shortcut to the weather

A white keyring carries a raised black QR code. A phone scans the code and opens the Netanya weather page. The address is fixed, while the website can be updated without printing a new keyring. Keep the repository name and published address stable: changing them can break already printed codes.

פרסום כתובת קבועה באמצעות GitHub Pages

משתמשים בחשבון GitHub בשם haymvi ובמאגר netanya-weather. בפרויקט חדש יוצרים את המאגר, מוסיפים index.html ושומרים commit בענף main. תחת Settings → Pages בוחרים “Deploy from a branch”, ואז main ו־/(root), ושומרים. אם המאגר כבר נפרס באמצעות Actions, משאירים את תהליך הפריסה הקיים. ממתינים לסיום הפריסה ופותחים את הכתובת בטלפון. כתובת הפרויקט היא https://haymvi.github.io/netanya-weather/.

תיעוד היסטורי: המאגר והעמוד המקורי כבר היו קיימים בתחילת העבודה המתועדת. אלה הוראות לפרסום חוזר, ולא טענה שיצירת החשבון או הפריסה הראשונה התרחשו בשיחה זו.

Publish a permanent address with GitHub Pages

Use the GitHub account haymvi and repository netanya-weather. For a new project, create the repository, add index.html, and commit it to main. In Settings → Pages, choose “Deploy from a branch”, then main and /(root), and save. If the repository already uses an Actions deployment, keep that workflow instead. Wait for the Pages deployment to finish and open the published address on a phone. The resulting project URL is https://haymvi.github.io/netanya-weather/.

History: the repository and its original page already existed when this documented session began. These are reproducible publication instructions, not a claim that account creation or the first deployment happened in this session.

בניית עמוד מזג האוויר

היישום המקורי היה עמוד HTML סטטי אחד עם CSS ו־JavaScript. הגרסה המתמקדת בגלישה משאירה את index.html ומוסיפה את sports.js ו־sports.css; יש לפרסם את שלושתם יחד. אין שרת יישום, התקנת חבילות או מפתחות API. הקוד מבקש תחזית מ־Open-Meteo ונתוני ים מ־Marine API עבור קו רוחב 32.3215, קו אורך 34.8532 ואזור זמן Asia/Jerusalem. הוא מציג תנאים נוכחיים, גרפים שעתיים, חמישה ימי תחזית ונתוני ים, ומתעדכן כל 15 דקות. עברית מוצגת מימין לשמאל ואנגלית משמאל לימין. בחירת השפה נשמרת במכשיר. הנתונים הם תחזיות מודל ולא מדידות מתחנה מקומית.

Build the weather page

The original application was one static HTML page with inline CSS and JavaScript. The surf-focused revision keeps index.html and adds sports.js and sports.css; all three must be published together. It has no backend, package installation or API keys. JavaScript requests the public Open-Meteo forecast API and marine API for latitude 32.3215, longitude 34.8532, and timezone Asia/Jerusalem. It displays current conditions, hourly charts, five daily cards and sea conditions, and refreshes every 15 minutes. Hebrew uses right-to-left layout; English uses left-to-right layout. The chosen language is stored locally. API data are model forecasts, not local station measurements.

קידוד הכתובת ושמירה על גאומטריית ה־QR

מקודדים את כתובת ה־HTTPS המדויקת, כולל /netanya-weather/, באמצעות מחולל QR ובודקים את התמונה בטלפון לפני יצירת מודל. משתמשים בריבועים שחורים על רקע לבן ומשאירים לפחות ארבעה מודולים ריקים סביב הקוד. מבליטים את הדוגמה השחורה כחלק נפרד ושומרים על יישור לבסיס.

בעבודה זו המשתמש סיפק את הקובץ Netanya_Weather_AD5X_Branco1_Preto2.3mf. המשתמש אישר ש־ChatGPT יצר את קובץ ה־3MF בשיחה קודמת, בהנחייתו ועם התאמות קטנות מצדו. פקודות יצירת המודל מהשיחה הקודמת אינן נמצאות בסביבת העבודה הזו, ולכן הערכה משמרת את הקובץ המקורי המדויק במקום להמציא היסטוריית פקודות חסרה. הקוד מפוענח לכתובת שלמעלה. רוחב הגוף 48 מ״מ, הגובה הכולל 60.899975 מ״מ, עובי הבסיס והטבעת הלבנים 1.2 מ״מ, קוטר החור 6 מ״מ והבליטה השחורה 1 מ״מ: עובי כולל של 2.2 מ״מ באזורים השחורים. רוחב הדוגמה 34.86 מ״מ והשוליים הצדדיים הנומינליים 6.57 מ״מ. מרכז החור שונה מעט ממרכז הטבעת החיצונית; התאמת מעגל לשפת החור מאשרת קוטר של 6 מ״מ.

Encode the URL and preserve the QR geometry

Encode the exact HTTPS URL, including /netanya-weather/, using a QR generator; test that generated image on a phone before making a model. Use black modules over a white background with at least four empty modules around the code. Extrude the black pattern as a separate part and keep its position aligned with the base.

For this job, the user supplied Netanya_Weather_AD5X_Branco1_Preto2.3mf. The user confirms that ChatGPT created this 3MF in an earlier chat; the user directed the project and made small adjustments. The earlier CAD-generation commands are not present in this workspace, so the kit preserves that exact original file instead of inventing a missing command history. Its QR decodes to the URL above. It has a 48 mm-wide body, overall height 60.899975 mm, a 1.2 mm white base and ring, a 6 mm hole, and 1 mm of raised black material: total black-area thickness 2.2 mm. The black pattern is 34.86 mm wide, leaving a nominal 6.57 mm side margin. The hole is slightly offset from the outside ring’s centre; fitting its circular boundary confirms its 6 mm diameter.

בדיקת ה־3MF לפני חיתוך לשכבות

קובץ 3MF הוא ארכיון ZIP. בודקים את תקינות הארכיון ואת הקבצים 3D/3dmodel.model ו־Metadata/model_settings.config. בחלק הלבן 2,304 קודקודים ו־4,608 משולשים; בשחור 1,544 קודקודים ו־3,188 משולשים. שתי הרשתות נמצאו סגורות, ללא קצוות פתוחים, קצוות לא־מניפולד או משולשים מנוונים. הלבן נמצא בגובה Z=0–1.2 מ״מ והשחור ב־Z=1.2–2.2 מ״מ. האקסטרודרים הלוגיים 1 ו־2 משויכים ללבן ולשחור בהתאמה.

OrcaSlicer 2.3.1 קרס בטעינת מטא־נתוני המשטח שסופקו. הפתרון היה יצירת עותק 3MF זמני עם XML הרשתות המקורי ללא שינוי ועם שיוכי החומרים, ללא מטא־נתוני המשטח והפרויקט שגרמו לתקלה. לא בוצעו שינוי קנה מידה, שינוי צורה או הפרדה של ריבועי ה־QR.

Inspect the 3MF before slicing

A 3MF is a ZIP archive. Check archive integrity, then inspect 3D/3dmodel.model and Metadata/model_settings.config. The white part has 2,304 vertices and 4,608 triangles; black has 1,544 vertices and 3,188 triangles. Both meshes were closed, with no boundary edges, non-manifold edges or degenerate triangles. White occupies Z=0–1.2 mm and black Z=1.2–2.2 mm. Logical extruders 1 and 2 are assigned to white and black respectively.

OrcaSlicer 2.3.1 crashed when loading the supplied plate metadata. The workaround was a temporary 3MF containing the original mesh XML unchanged and the object/part material assignments, without the incompatible plate/project metadata. No scaling, reshaping or separation of QR modules was performed.

שימוש בפרופילי AD5X ובקוטר הנחיר שאושר

המשתמש אישר נחיר בקוטר 0.4 מ״מ. הפרופילים נלקחו מהמאגר הרשמי FlashForge/Orca-Flashforge, ב־commit c45cc8216c184574c36873314ae7caea67c7a1ad: מדפסת Flashforge AD5X 0.4 nozzle, תהליך 0.20mm Standard @FF AD5X וחומר Flashforge PLA Basic @FF AD5X. ההגדרות שעברו בירושה אוחדו לפרופילי JSON מלאים. מותג הפילמנט לא נמסר; PLA Basic הוא פרופיל הבסיס שנבחר, לא כיול שנמדד לפילמנט המסוים.

בגרסת Flashforge שנבדקה היו מתקינים ל־Windows ול־macOS. החיתוך בפועל כאן בוצע באמצעות OrcaSlicer 2.3.1 AppImage ללינוקס, ולא בקובץ הרצה של Orca-Flashforge. ספריות WebKit, JavaScriptCore, HarfBuzz ICU, Manette, Hyphen ו־HIDAPI החסרות הורדו ממאגרי Debian עם אינדקסים חתומים וחולצו מקומית. אימות TLS וחתימות נשמר.

Use the AD5X profiles and the confirmed nozzle

The user confirmed a 0.4 mm nozzle. Profiles came from the official FlashForge/Orca-Flashforge repository, commit c45cc8216c184574c36873314ae7caea67c7a1ad: Flashforge AD5X 0.4 nozzle, 0.20mm Standard @FF AD5X, and Flashforge PLA Basic @FF AD5X. Inherited settings were resolved into complete JSON profiles. The actual filament brand was not provided; PLA Basic is the selected baseline, not a measured filament calibration.

The official Flashforge release checked offered Windows/macOS installers. Slicing here actually used the official Linux OrcaSlicer 2.3.1 AppImage, not an Orca-Flashforge executable. Missing WebKit, JavaScriptCore, HarfBuzz ICU, Manette, Hyphen and HIDAPI libraries were downloaded from signed Debian package indexes and extracted locally. TLS/signature verification was retained.

חיתוך ל־11 שכבות והחלפת צבע אוטומטית אחת

מגדירים גם את גובה השכבה הרגילה וגם את הראשונה ל־0.20 מ״מ. בפרופיל הרשמי השכבה הראשונה היא 0.25 מ״מ, ולכן יש לשנות אותה כדי לקבל שש שכבות לבנות מדויקות. מניחים את הבסיס שטוח כשהקוד כלפי מעלה, מבטלים תמיכות ומשאירים מילוי של 100%. שכבות 1–6 מסתיימות בגובה Z=1.2 מ״מ ומשתמשות ב־T0 — לבן בערוץ 1. שכבות 7–11 מסתיימות ב־Z=2.2 מ״מ ומשתמשות ב־T1 — שחור בערוץ 2. ההחלפה היחידה מתרחשת לפני הדפסת Z=1.4 מ״מ. מגדל ניקוי נפרד מייצב את הזרימה לאחר החלפת IFS; נפח השטיפה המחושב מלבן לשחור הוא 80 מ״מ מעוקב.

פרופיל המדפסת השמור מוסיף איפוס צירים והמתנה לחימום לפני תנועות ההכנה הרשמיות, ובסיום הרמת Z וכיבוי החימום. שתי הגרסאות משתמשות ב־215 מעלות בתחילה, 210 בהמשך ומשטח PEI מחוספס ב־60 מעלות. הרטרקציה היא 0.8 מ״מ במהירות 30 מ״מ לשנייה. בתחילת ההדפסה בודקים את מיפוי ערוצי IFS במסך המדפסת, משום שהקושחה מאפשרת לשנות שיוכים.

Slice eleven layers and one automatic colour change

Set both normal and first-layer heights to 0.20 mm. The official process starts at 0.25 mm, so that first-layer override is necessary for six exact white layers. Place the base flat with the QR facing up; disable supports and retain 100% infill. Layers 1–6 end at Z=1.2 mm and use T0 (white, channel 1). Layers 7–11 end at Z=2.2 mm and use T1 (black, channel 2). The single change occurs before printing Z=1.4 mm. A separate prime tower stabilises the flow after the IFS change; calculated white-to-black flush volume is 80 mm³.

The saved machine profile adds homing and a temperature wait before the official prime moves, plus a Z lift and heater shutdown at the end. Both versions use 215 °C initially, 210 °C subsequently, and a 60 °C textured PEI bed. Retraction is 0.8 mm at 30 mm/s. Check the printer’s IFS mapping at the start: firmware can permit slot remapping.

הבנת המהירות בקובץ הראשון ובגרסת המהירות הרשמית

בקובץ הראשון הופחתו המהירויות בכל המודל: קיר חיצוני ב־30, קיר פנימי ב־45 ומשטח עליון ב־25 מ״מ לשנייה. זו הסיבה לאיטיות. לבקשת המשתמש, הקובץ החדש משתמש במהירויות ובתאוצות של פרופיל AD5X הרשמי, ללא תקרת מהירות ביניים ידנית: קיר חיצוני 200, קיר פנימי 300, משטח עליון 200 ומעבר 500 מ״מ לשנייה. מילוי מלא מוגדר ל־250 ומילוי דליל ל־270 מ״מ לשנייה. תאוצת הקירות היא 5,000 ותאוצת המעבר 10,000 מ״מ לשנייה בריבוע.

בפרופיל המדפסת מגבלת מהירות XY היא 600 מ״מ לשנייה ומגבלת תאוצת XY היא 20,000 מ״מ לשנייה בריבוע. תהליך היצרן משתמש בכוונה במהירויות נמוכות יותר לפי סוג הפעולה; הקובץ פועל לפי התהליך הרשמי ולא קובע לכל תנועה את מגבלת החומרה.

פרופיל PLA הרשמי עדיין מגביל זרימה ל־21 מ״מ מעוקב לשנייה ומפעיל יעד קירור של 8 שניות. נשמרו גם הכללים הרשמיים להיקפים קצרים ולזיזים. אלה חלק מפרופיל המדפסת והחומר; הגדרת מהירות מרבית אינה אומרת שכל קטע QR קטן יגיע אליה.

הזמן המשוער יורד מ־30:24 ל־13:17 דקות, כ־56% פחות לפי תוכנת החיתוך. בשתי הגרסאות אותה גאומטריה, 11 שכבות והחלפת צבע יחידה. בהמשך המשתמש דיווח שההדפסה יצאה לבנה כולה. בדיקת החלפת הצבע הפיזית נכשלה; קריאות הקוד הפיזי טרם אושרה. תוצאת בדיקת ארבע השכבות עדיין ממתינה. גרסת המהירות הרשמית נבדקה דיגיטלית בלבד. זהו קובץ נפרד להדפסה עתידית ולא שינוי בהדפסה שכבר רצה.

The first file versus official AD5X speeds

The first file reduced speeds across the entire model: 30 mm/s outer walls, 45 mm/s inner walls and 25 mm/s top surfaces. That explains the slow print. At the user’s request, the new file uses the official AD5X process speeds and accelerations without an intermediate manual speed cap: outer walls 200, inner walls 300, top surfaces 200 and travel 500 mm/s. Solid infill uses 250 mm/s and sparse infill 270 mm/s. Wall acceleration is 5,000 mm/s² and travel acceleration 10,000 mm/s².

The machine profile lists XY speed limits of 600 mm/s and XY acceleration limits of 20,000 mm/s². The manufacturer’s process deliberately uses lower feature speeds; this file follows that official process rather than setting every movement to the hardware limit.

The official PLA profile still limits volumetric flow to 21 mm³/s and applies an 8-second cooling target. Official short-perimeter and overhang rules also remain in effect. These are part of the machine/material profile; commanded maximum speeds do not mean every tiny QR segment reaches them.

The estimated time falls from 30m24s to 13m17s, about 56% less slicer-estimated time. Both versions retain the same geometry, 11 layers and one colour change. The user subsequently reported that the print came out entirely white. Physical colour-change validation failed; physical QR readability remains unconfirmed. A later four-layer test is pending. The official-speed revision has digital validation only. It is a separate file for a future print, not a change to a running job.

בדיקת הפלט בפועל, הדפסה וסריקה

בודקים את קוד היציאה ואת קובץ התוצאה של Orca, ואז בוחנים את ה־G-code שיוצא בפועל. שם קובץ אינו הוכחת תקינות. סופרים גבהי שכבות וכלי אקסטרוזיה בפועל: שש שכבות לבנות בלבד ואחריהן חמש שחורות בלבד, עם מעבר צבע יחיד. מאמתים נחיר, היעדר תמיכות, המתנה לטמפרטורה ופקודות סיום. ZXing-C++ פענח גם את ההיטל של הרשת המקורית וגם תמונות שחושבו ממסלולי השכבה העליונה בכמה רזולוציות, וקיבל את הכתובת הנכונה.

במדפסת הוצג סמל מסמך במקום תמונה של החלק. בקבצים המקוריים לא הייתה תמונה ממוזערת תואמת. בגרסת IFS V3 נוספה תמונת PNG והמשתמש אישר שהיא מוצגת בשחור ולבן; החלפת צבע פיזית עדיין לא אושרה; הסמל כשלעצמו לא הוכיח כשל בחיתוך. בבדיקה פיזית מוודאים לבן בערוץ 1 ושחור בערוץ 2, בודקים היצמדות והחלפת צבע, ולאחר קירור סורקים בטלפון. פענוח דיגיטלי אינו מבטיח קריאות של ההדפסה הסופית.

Validate the real output, then print and scan

Check Orca’s exit status and result file, then inspect the exported G-code rather than trusting a filename. Count layer heights and actual extrusion tools: six white-only layers followed by five black-only layers, with exactly one effective transition. Confirm the nozzle, supports, temperature waits and shutdown commands. ZXing-C++ decoded both the original mesh projection and rasterised final-layer toolpaths at several image sizes to the expected URL.

The printer showed a document icon instead of a model thumbnail. The original files lacked a compatible thumbnail. The IFS V3 revision added a PNG preview, and the user confirmed seeing it in black and white; physical colour switching is still unconfirmed; the icon alone did not establish a slicing failure. For a physical test, confirm white in slot 1 and black in slot 2, inspect adhesion and the colour change, then scan the cooled part with a phone. Digital decoding does not guarantee the finished print’s readability.
